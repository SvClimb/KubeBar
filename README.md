# KubeBar

Приложение в строке меню macOS, которое собирает команду `kubectl` / `stern` / любой другой CLI-утилиты из выбранных контекста, namespace и приложения — и открывает её в терминале (по умолчанию Terminal.app; также Ghostty, iTerm2 или любой свой).

- выпадающие списки с поиском: утилита → контекст (из `~/.kube/config`) → namespace → приложение (Deployment/StatefulSet/DaemonSet);
- предпросмотр команды, который можно поправить перед запуском или скопировать кнопкой;
- **Запустить** — открыть терминал и выполнить; **Подготовить** — открыть терминал с набранной, но не запущенной командой;
- свои шаблоны утилит с плейсхолдерами `{executable} {context} {namespace} {app}`, их экспорт и импорт в JSON;
- история последних 10 команд с повторным запуском;
- интерфейс на русском и английском — по языку системы (или вручную: **Настройки KubeBar → Общие → Язык**).

Требуется macOS 14+ и установленный `kubectl` (плюс `stern` и т.п. — по желанию).

## Установка

```sh
brew install --cask svclimb/tap/kubebar
```

Обновление — `brew update && brew upgrade --cask kubebar` (без `brew update` brew может не сразу увидеть новую версию), удаление — `brew uninstall --cask kubebar` (с `--zap` — вместе с настройками).

Иконка появится в строке меню (значок терминала); в Dock приложения нет. При первом запуске команды macOS спросит разрешение на управление терминалом — нажмите «Разрешить». Если случайно отказали: **Системные настройки → Конфиденциальность и безопасность → Автоматизация → KubeBar**.

## Настройка

Шестерёнка в окне KubeBar открывает настройки:

- **Утилиты** — шаблоны команд. В качестве исполняемого файла можно указать полный путь, если утилита не находится автоматически (KubeBar ищет в PATH вашего login-shell, `/opt/homebrew/bin` и `/usr/local/bin`). Кнопки **Экспорт…** / **Импорт…** сохраняют список утилит в JSON и загружают его обратно.
- **Терминал** — какой терминал использовать (по умолчанию Terminal.app). Для своего терминала `{{command}}` в шаблоне заменяется на собранную команду.
- **Namespaces / Apps** — сохранённые списки. Кнопка ↻ рядом с полем в меню подтягивает их из кластера; найденные так namespaces/apps показываются только для своего контекста.
- **История** — последние 10 команд; правый клик по записи — запустить или подготовить снова.
- **Общие** — запуск при входе в систему и язык интерфейса.

Настройки хранятся в `~/Library/Application Support/KubeBar/config.json`.

## Примеры конфигурации

### Шаблон утилиты

Шаблон — это строка, в которой KubeBar подставляет выбранные значения:

| Плейсхолдер | Что подставляется |
|---|---|
| `{executable}` | исполняемый файл утилиты (`kubectl`, `stern`, алиас `k` или полный путь) |
| `{context}` | контекст из `~/.kube/config` |
| `{namespace}` | namespace |
| `{app}` | приложение (Deployment/StatefulSet/DaemonSet); если `{app}` в шаблоне нет, поле приложения в меню не показывается |

Несколько готовых шаблонов:

| Имя | Исполняемый файл | Шаблон команды |
|---|---|---|
| stern | `stern` | `{executable} --context {context} -n {namespace} {app}` |
| stern за час | `stern` | `{executable} --context {context} -n {namespace} {app} --since 1h --timeout 30m` |
| логи деплоймента | `kubectl` | `{executable} --context {context} -n {namespace} logs -f deployment/{app}` |
| поды приложения | `kubectl` | `{executable} --context {context} -n {namespace} get pods -l app={app} -o wide` |
| k9s | `k9s` | `{executable} --context {context} -n {namespace}` |

Если нужно несколько вариантов одной утилиты — добавьте несколько строк с одним исполняемым файлом и разными именами/шаблонами.

### Пример: логи деплоймента через kubectl

1. Откройте **Настройки KubeBar → Утилиты** и нажмите **Добавить утилиту**.
2. Заполните поля:
   - **Имя (как показывается в меню)**: `логи деплоймента`;
   - **Исполняемый файл или путь**: `kubectl`;
   - **Шаблон команды**: `{executable} --context {context} -n {namespace} logs -f deployment/{app} --tail 100`.
3. Проверьте строку **Предпросмотр** внизу редактора и нажмите **Сохранить**.
4. В меню KubeBar выберите утилиту «логи деплоймента», контекст, namespace и приложение. В предпросмотре появится, например:
   ```
   kubectl --context prod -n backend logs -f deployment/my-app --tail 100
   ```
5. Нажмите **Запустить** — откроется терминал с логами. Нужно один раз поменять `--tail 100` на `--tail 10`? Поправьте команду прямо в предпросмотре: шаблон утилиты при этом не изменится.

### Пример: алиас вместо kubectl

Если в `~/.zshrc` есть `alias k=kubectl`, укажите в утилите **Исполняемый файл или путь**: `k`. В Terminal.app и Ghostty команда набирается в обычной интерактивной оболочке, поэтому алиасы работают как есть. В iTerm2 «Запустить» выполняет команду в обход оболочки, и алиасы там срабатывают только через «Подготовить».

### Пример: перенос утилит на другой Mac

1. На исходном Mac: **Настройки KubeBar → Утилиты → Экспорт…**, сохраните `KubeBar-utilities.json`. Файл выглядит так:
   ```json
   [
     {
       "commandTemplate" : "{executable} --context {context} -n {namespace} {app}",
       "executable" : "stern",
       "name" : "stern"
     },
     {
       "commandTemplate" : "{executable} --context {context} -n {namespace} logs -f deployment/{app} --tail 100",
       "executable" : "kubectl",
       "name" : "логи деплоймента"
     }
   ]
   ```
2. На другом Mac: **Настройки KubeBar → Утилиты → Импорт…**, выберите этот файл.
3. Утилиты с совпадающими именами заменятся, новые добавятся в конец списка; остальные утилиты останутся как были. Под списком появится, сколько добавлено и сколько заменено.

Тот же файл удобно хранить в репозитории команды и править вручную.

### Пример: другой терминал

1. **Настройки KubeBar → Терминал**, в поле **Имя нового профиля** введите название приложения (например, `Alacritty`) и нажмите **Добавить**.
2. Профиль создастся с шаблонами вида `open -na "Alacritty" --args -e {{command}}` — это подходит терминалам, которые принимают команду через `-e`. Для других поправьте **Команду запуска** по документации терминала; `{{command}}` заменяется на собранную команду, строка выполняется через `/bin/zsh -lc`.
3. **Команда подготовки (без выполнения)** по умолчанию копирует команду в буфер обмена и открывает терминал — останется вставить её через ⌘V. Оставьте поле пустым, если режим «Подготовить» не нужен.
4. Выберите профиль в **Активный терминал**.

## Сборка из исходников

Нужны Xcode Command Line Tools (`xcode-select --install`).

```sh
Packaging/build-app.sh          # собрать dist/KubeBar.app и запустить его вместо текущего KubeBar
Packaging/build-app.sh --zip    # собрать dist/KubeBar-<версия>.zip для раздачи
```

Сборка универсальная (Apple Silicon + Intel), подпись ad-hoc. Скрипт не трогает `/Applications` — там живёт копия, установленная через brew; чтобы вернуться к ней после проверки, закройте dev-сборку и выполните `open -a /Applications/KubeBar.app`.

## Выпуск новой версии

```sh
git tag v1.1 && git push origin v1.1
```

GitHub Actions (`.github/workflows/release.yml`) соберёт `KubeBar-1.1.zip` (версия берётся из тега), опубликует релиз и обновит cask в [svclimb/homebrew-tap](https://github.com/svclimb/homebrew-tap).

Строки интерфейса в коде — на английском, они же ключи перевода; русский перевод в `Packaging/Localization/ru.lproj/Localizable.strings`. При `swift run` интерфейс всегда английский: переводы подключаются только в собранный `.app`.
